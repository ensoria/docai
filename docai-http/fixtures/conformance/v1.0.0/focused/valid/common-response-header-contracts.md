# valid: common response-header contracts and endpoint deviations

Expected: valid complete conformance. Common caller-relevant response-header contracts can live in `CONVENTIONS.md`; endpoint response-header `none` means no status-specific addition, while endpoint-level suppression or override of a common header is marked with a response-local `**deviation**:`.

````markdown
# API Conventions

## HTTP Semantics

The following response headers apply to every endpoint response unless a response section states a `**deviation**:`.

| Name | Type | Presence | Meaning |
|---|---|---|---|
| X-Request-ID | string | always | Request correlation ID; log it with client-side error reports |
| ETag | string | present when the response represents a cacheable resource | Use as `If-None-Match` on subsequent reads |

---

## GET /reports/{id}

Gets one report.

### Response 200

**body_presence**: always

**media_type**: application/json

**body_nullable**: no

```json
{"id":"rpt_01K0COMPLETE","status":"ready"}
```

| Field | Type | Presence | Nullable | Meaning |
|---|---|---|---|---|
| id | string | always | no | Report ID |
| status | string | always | no | Report state |

- Response Headers: none

The common `X-Request-ID` and `ETag` contracts from `CONVENTIONS.md` still apply; this response has no status-specific header additions.

### Response 202

**deviation**: this response overrides the common `ETag` response-header contract; pending reports are not cacheable and do not include `ETag`.

**body_presence**: always

**media_type**: application/json

**body_nullable**: no

```json
{"id":"rpt_01K0COMPLETE","status":"processing"}
```

| Field | Type | Presence | Nullable | Meaning |
|---|---|---|---|---|
| id | string | always | no | Report ID |
| status | string | always | no | `processing` |

#### Response Headers

| Name | Type | Presence | Meaning |
|---|---|---|---|
| Retry-After | int | always | Seconds to wait before polling again; example `Retry-After: 5` |

### Response 304

**deviation**: this response suppresses the common `X-Request-ID` and `ETag` response-header contracts because it is generated by an external CDN cache validator.

none

- Response Headers: none
````
